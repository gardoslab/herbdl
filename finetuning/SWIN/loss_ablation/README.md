# Loss-function ablations (SWIN-Base, 384px)

Nine margin / hierarchical losses compared on Herbarium 2022 (15,501 species), then a
scaling ladder to 64k species, then the same losses on other backbones (ConvNeXt, DINOv2,
CoAtNet, EfficientNet) and ensembles of the saved predictions. All training goes through
`finetuning/SWIN/SWIN_finetuning_advanced.py` + `train_advanced.sh` with a YAML config.

## Code (`finetuning/SWIN/loss_ablation/`)

| File | What it is |
|---|---|
| `losses.py` | Classifier heads: softmax, ArcFace / sub-center ArcFace, KappaFace, X2-Softmax, DBM |
| `hierarchy.py` | HACE (species / genus / family tree head) and `TaxonomyTree` |
| `aux.py` | Extra losses on top of a head: ECC, TARA (needs `bioclip_teacher.py`) |
| `grad_modulation.py` | FlexiGrad primitives (not wired into training yet) |
| `model.py` | `SwinWithLoss`: SWIN backbone + any head / hierarchy / aux combination |
| `checkpoint_io.py` | Geometry export used by `repgeom` (`mode: loss_ablation_geometry`) |
| `e2e_harness.py`, `*_smoke.py` | End-to-end and smoke tests (40 species, real images) |
| `build_ladder.py` | Builds the nested 15.5k / 32k / 64k species sets from the merged 2021+2022 data |
| `phase3_per_species.py` | Per-species F1 by rarity, error structure, paired bootstrap |
| `phase3_geometry.py` (+ `repgeom_geometry.py`) | Feature-space geometry per model (same metrics as repgeom) |
| `rare_crossover.py` | KappaFace vs DBM by training-image count, and the routing test |
| `backbones.py`, `backbones_smoke.py` | Pooled-feature adapters so `SwinWithLoss` sits on ConvNeXt, DINOv2, EfficientNet or a timm model (CoAtNet); CPU smoke test |
| `part4_ensemble.py` | Vote / rank-fusion / routing ensembles of saved top-1 and top-5 answers, with the either-correct ceiling |
| `part4_leakage.py`, `copy_gallery.py` | Same-specimen copies between train and validation (full `val_2022`), every model re-scored without them; picture sheets of the flagged pairs |
| `geometry_by_rarity.py`, `geometry_fixed_n.py` | Separation gap by number of training images per species; the fixed-n version uses 2 validation images per species (the plain version is confounded by validation counts) |
| `near_duplicates*.py`, `ladder_*.py`, `kappaface_wins.py`, `routing_counts.py` | Ladder-side analyses: near-duplicates, routing, per-count breakdowns |
| `run_*.sh` | SCC wrappers (env setup inside the script) |

## Trainer options added for this work (`SWIN_finetuning_advanced.py`)

- `hace:` and `loss_registry:` config sections (head, head_kwargs, aux, aux_log_steps)
- `training.resume_from_checkpoint: newest` (most recently saved checkpoint, not highest step)
- `training.max_steps` (fixed step budget; used by the scaling ladder)
- `evaluation.init_weights` / `predictions_path` / `features_path` (eval-only re-scoring)
- Heavy augmentation on registry heads: `augmentation.use_advanced` with `randaugment`, `mixup`, `cutmix`,
  `mixup_cutmix_prob`, `label_smoothing`, and `augmentation.warmup_epochs` (strength ramps linearly 0 -> 1:
  RandAugment applied with probability s, mixup/CutMix with probability prob*s, smoothing eps*s).
  `SwinWithLoss.forward(..., labels_b, lam, label_smoothing)` computes lam*L(y_a) + (1-lam)*L(y_b),
  margin applied once per label set. Refused together with `aux` or logit adjustment.
- `loss_registry.margin_warmup_epochs` ramps the margin of a registry ArcFace head (native ArcFace has `arcface.margin_warmup_epochs`)
- Logit adjustment (`long_tail.logit_adjustment`) works on the registry `softmax` head only (balanced softmax, training only)
- Stock (non-registry) models can save per-image predictions too (`evaluation.predictions_path`), and timm models
  (CoAtNet) get their image-processor attributes shimmed
- Multi-GPU evaluation now gathers predictions from all ranks (before this fix, 2-GPU runs
  were scored on half the validation set)

## Configs (`finetuning/SWIN/configs_advanced/`)

- `swin_base_384_*_pilot.yml`, `swin_base_384_arcface_ablation.yml`: one real-scale run per
  loss (`*_seed43.yml`: same run, seed 43; `swin_base_384_x2softmax_s64.yml`: scale 64)
- `swin_base_384_ladder_{n15k,n32k,n64k}_{dbm,arcface,kappaface}.yml`: scaling ladder
  (generated by `gen_ladder_configs.py`); `swin_base_384_ladder_smoke.yml`: 64k smoke test
- `backbones/`: Part 4 training configs, `{convnext,dinov2,coatnet,efficientnet}_{ce,ce_la,arcface,dbm}.yml`
  (llindon's recipe per backbone; `generate.py` regenerates them), and `backbones/eval/` for eval-only re-scoring
- `backbone_eval/`, `backbone_eval/full/`: re-scoring configs for llindon's cross-entropy checkpoints
  (`full/` removes his `max_eval_samples: 50000` cap)
- `swin_base_384_ce.yml`, `swin_base_384_ce_la.yml`: cross-entropy baselines through the registry softmax head
- `swin_base_384_dbm_heavyaug.yml`: DBM with RandAugment, mixup/CutMix and label smoothing ramped in over 10 epochs
- `swin_large_384_arcface_hybrid_multitask*.yml`: SWIN-L ArcFace-hybrid variants (kaggle22 v3, v4/v5)
- `phase3_eval/`, `phase3_geom/`: eval-only re-scoring configs (generated, see `generate.py`)

KappaFace and ECC must run on 1 GPU (per-species buffers are not synced across GPUs).

Results and the full write-up live in the project's tracking document
("Loss Function Ablations.md"), not in this repository.
